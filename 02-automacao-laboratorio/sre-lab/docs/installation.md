# Instalação e manutenção

Siga o README. `make preflight` consulta host/rotas/VMs sem provisionar. `make bootstrap` obtém ferramentas isoladas, verifica o commit, prepara venvs e renderiza o chart. `make provision` cria VMs uma por vez, registrando UUID. `make prepare` confirma SSH e IPs, gera inventários e executa preflight/prepare/verify do Ansible. `make cluster` aplica a tag do Kubespray uma única vez em VMs novas, obtém o kubeconfig, confirma CA/UID e verifica nós. `make kubeconfig` valida o registro existente ou obtém o acesso após a instalação autorizada. `make addons` instala MetalLB, Local Path e Traefik. `make validate` consulta o estado real. `make install` encadeia. `make status` não altera nada. `make start` e `make stop` preservam discos; não criam novas VMs intencionalmente. `make ssh NODE=...` exige identidade e chaves registradas.

Estado local: `.local/identity.json`, `vagrant-state`, `known_hosts`, `ssh-fingerprints.json`, `inventory`, `upstream`, `ansible`, `kubespray`, `bin`, `downloads`, `sre-lab.kubeconfig`. Não mover ou apagar esses arquivos entre instalações. Se perder estado, o código não adota VMs por nome. A senha/chave não é impressa pelos scripts; os processos upstream podem gerar saída própria, não publicar logs brutos.

Antes de upgrades, revise suporte e compatibilidade e faça backup dos dados de laboratório. Não altere versões ou config depois de provisionar: hash divergente bloqueia. Não há procedimento automático de migração. Certificados podem vencer se o laboratório ficar desligado; verifique TLS, datas e documentação da tag. Não desative validação TLS.
